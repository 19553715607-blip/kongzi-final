# 第一篇　平台说明

> 让海外读者用母语读《论语》，也能上手玩一遍。

---

### 一、平台是什么

「孔子」是一个面向全球的儒家文化交互平台。除了多语言译本，它把《论语》做成能提问、能玩、能被海外机构嵌进自己网站的形式。

---

### 二、为什么做

中文经典的外译，大多止于译得准。海外读者读完《论语》，还是不知道仁、礼、中庸这些概念怎么用；抽象的东西没有可上手的地方；儒家跟基督教、伊斯兰、现代世俗的分歧，也很少有人讲清楚。

我们做的三件事：多智能体问答、知识图谱、游戏化。

---

### 三、给谁用

| 用户群 | 使用场景 |
|---|---|
| 海外高校师生 | 在母语界面查典籍、跟 AI 对话、玩六艺、写论文 |
| 海外文化机构 | 通过开放 API 把儒家语义嵌入自己的网站、App、课程 |
| 国内年轻人 | 短视频流式刷金句、游戏化打卡、与朋友分享 |
| 研究者 | 经典溯源、跨文明比较、知识图谱钻取 |
| 校园终端 | 孔子学院、文化中心的展示屏交互入口 |

---

### 四、核心能力（五个）

#### 1. 智能对话

关于儒家的问题，由 Qwen-Plus 大模型加多智能体协同回答。每条回答都绑定经典原文出处，可以点开溯源，并附三项校验评分：文本依据 / 现代发挥 / 文化适配。中 / 英 / 法 / 西 / 阿 5 语实时切换。

#### 2. 六艺游戏化修身

古代「礼乐射御书数」做成了 6 个独立游戏：

- 礼 — 3D 第三人称庭院「执礼 · 宾至如归」：迎宾次序、揖礼深浅、安席位次、席间照应，考「敬 · 序 · 节」
- 乐 — 32 拍五音填序，体验「和而不同」
- 射 — 3D 射场，反求诸己，连中三发会触发"射不主皮"提示
- 御 — 2D 马车，体验"礼以行之、不极不躁"
- 书 — 三玩法：选字 / 拼字 / 笔顺
- 数 — 滑块公平分配（不患寡而患不均）

每艺都有关联经典原文解锁和五品评级，六艺另有总览、勋章墙和群体排行。

#### 3. 跨文明对话

气候 / 技术 / 社会 / 个人 / 治理 5 个全球议题下，用 2,500 个对话案例展示儒家与古希腊、基督教、伊斯兰、现代世俗的立场对比。

#### 4. 知识图谱

人物 / 概念 / 篇章 / 命题 / 学派五类节点连成可视化关系网，支持邻域钻取和两点最短路径，后端是 Neo4j 真实图库。

#### 5. 开放接口

海外机构可以在线申请 API Key，配额 10,000 次/月。目前已对接 8 家高校与文化机构：Harvard、Stanford、Cornell、Sorbonne、Oxford、Keio、首尔大、旧金山孔子学院。

---

### 五、体验亮点

- **无登录墙**：首次访问自动发游客号，读经、图谱、对话、六艺、案例、术语、小测、刷刷、评论点赞、收藏、签到都能直接用。成就勋章与今日修行任务需要登录，游客点到时给解锁引导，不拒绝访问。
- **五语全栈**：界面、AI 回答、典籍原文都覆盖中 / 英 / 法 / 西 / 阿。
- **三端响应式**：桌面 / 手机 / 平板一套代码，触屏游戏单独优化过。
- **隐私合规**：按 GDPR / CCPA 提供数据导出与账户删除。
- **暗黑 / 护眼主题**：暖调深色，切换不闪烁。

### 六、海外接入方式

```
机构访问 /developers
   ↓
填写表单一键申请
   ↓
后台自动审批 + 发 Demo Key
   ↓
立即调用 /api/v1/public/passages 等接口
   ↓

```

接入方式有三种：REST API（curl / Python / JS 示例提供）、iframe 嵌入金句卡、SVG 海报卡（1200×630，可发推/朋友圈）。

### 七、当前进展

对照申报书的目标，多语言语料从要求的 10 万条做到 11.4 万条，跨文明对话案例从 500 个做到 2,500 个，两项均已达标。其余三项尚有差距：海外机构接入目标 20 家，目前 8 家；平台用户目标 5 万师生，目前 389 人；平台访问目标 50 万人次，目前 3,889 次。

六艺游戏 6 个全部上线，技术架构和内容主体已就位，接下来的重点是用户与机构推广，以及演示场景的完善。

### 一、首屏与核心入口（八大界面）

#### 1. 首页 `/`
首页展示今日金句卡，从后端实时拉取经典原文、译文和出处；下方是聊一聊、读一读、知识图谱三个入口，页面带加载骨架屏。

#### 2. 刷刷 · 短视频流 `/feed`
TikTok 式全屏暗黑沉浸卡片，垂直滑动翻页；大字艺术化原文配译文和出处 chip，AI 人格署名轮播（子曰君 / 小颜回 / 庄生 / 现代小张 / 诗哥），配年轻化标签（#做个温暖的人 #i人友好 #emo自救）；右侧动作栏有点赞、评论、分享、壁纸、收藏；另有轻量埋点（visitor_id + path + device + source）。

#### 3. 读一读 · 经典阅读 `/read`
典籍 / 章 / 句三级导航；五层信息可独立开关：原文 / 拼音 / 译文 / 注释（朱熹注 + 现代释义）/ AI 解读；中 / EN / FR / ES / AR 五语切换（内容级翻译）；收藏接入游戏化与个人中心；可跳转「问 AI 解读」直通对话页。

#### 4. 智能对话 `/chat`
SSE 流式逐字回答；多智能体协同可视化（总控 / 检索 / 合成 / 校验 / 翻译 / 跨文明）；经典依据卡（朱砂左边框 + 原文 + 出处，可点击溯源）；校验徽章三评分：文本依据 / 现代发挥 / 文化适配；带推荐追问 chips 和多轮会话持久化。真实 LLM 已上线：Qwen-Plus（DashScope）生产可用，可一键切回 mock / OpenAI / Anthropic；支持 5 语切换（自动激活翻译 + 跨文明智能体）。

#### 5. 知识图谱 `/graph`
ECharts 力导向图，五类节点：人物 / 概念 / 篇章 / 命题 / 学派；中文关系标签：师承 / 相关 / 提及 / 论及 / 提出 / 属于 / 出自；单击查关系、双击钻取，邻域深度 1/2/3。后端接 Neo4j 真实图库（125 节点 / 33 关系），可降级为内存图。

#### 6. 君子之路 `/journey` —— 平台游戏化核心
总览模块（新）含：段位（童生→秀才→举人→进士→翰林）+ 总 XP + 连续打卡；「君子之路 · 六艺总览」总分 X/600 + 5 级称号（未起步 / 始入门 / 习艺之人 / 博学君子 / 六艺通才 / 君子大成）；6 张艺卡带分数进度条 + 等级（神/妙/中/试/未起）+ 一键跳对应游戏；「君子勋章墙」8 枚：6 单艺勋章（习礼者 / 知音 / 反求诸己 / 执御君子 / 通文达诂 / 衡均）+ 2 综合勋章（六艺通才 / 君子大成）；「群体排行」Top 10（按总分），同名游客自动去重，自己永远上榜 + 高亮；另有今日修行（3 任务）+ 系统勋章。

#### 7. 个人中心 `/me`
头像名片（段位 / XP / 连击 / 游客标识）；游客绑邮箱升级为正式账号，进度保留；收藏夹 / 勋章墙摘要；GDPR / CCPA 数据导出（下载 JSON）+ 账户删除。

#### 8. 概念图鉴 `/concepts` — 前端页面缺失
后端 API 已就绪：`GET /api/v1/concepts` · `/concepts/{id}`（195 概念多语定义、161 多语术语，5 语）。但前端**无独立路由**：`api.ts` 的 `getConcept` 已定义但无任何页面调用，稀有度系统（常规 / SR / SSR）与按学派筛选仅停留在设计稿。待办：补 `/concepts` 图鉴页，或将该入口从文档下架。

- JWT (HS256) 自包含 + PBKDF2 密码哈希，仅用 Python 标准库实现

- **能力分层**：游客可使用全部内容功能，进度照常累计（XP / 连签 / 六艺进境都真实记录）；
  **成就勋章**与**今日修行任务**为登录专属，接口层对游客返回 403，前端以锁定卡 + 解锁弹窗承载
- **进度不丢**：游客态积累的 XP、六艺进境、收藏、勋章，在登录已有账号时由 `X-Guest-Token`
  自动并入（XP 相加、六艺逐项取高、收藏去重迁移）；游客绑邮箱升级则原地转正，天然保留
- 邮箱注册 / 登录 / 游客升级，进度保留
- 管理员通过 `.env` 邮箱白名单授予（非 self-promote 端点）
- GDPR / CCPA 合规：数据导出（JSON 全量）+ 账户删除
- CORS regex 覆盖 RFC1918 私网（任意 IP:任意端口）+ 通配 localhost

### 一、平台定位

这是一个面向全球用户的多终端儒家语义交互平台，由多智能体协同完成经典检索、概念解释、推理校验、教学引导、跨语言传播与跨文化解释。无论用户来自哪个国家、使用哪种语言、在哪类设备上、处于哪个年龄段，都能以适合自己的方式理解儒家思想，设计上优先照顾 Z 世代的使用习惯。

---

### 二、定位演进

定位演进大致分四步：v1 是 RAG 智能问答平台，v2 转向多智能体驱动的语义交互，v3 扩展到多终端加多语言全球化，v4 进一步面向 Z 世代做友好交互。

### 四、智能体体系（10 类）

10 类智能体的分工：总控智能体理解用户意图、分解任务、调度其余智能体并汇总结果；经典检索智能体从原文库返回出处、原文、译文与注释；概念解释智能体解释儒家核心概念，并区分不同思想家的差异；知识图谱智能体查询人物、概念、篇章之间的关联；教学引导智能体按用户水平定制内容、生成学习路径并提出追问；回答校验智能体检查回答依据，区分原义与现代发挥，降低幻觉；多语言翻译智能体负责输入识别、译文生成与术语对照；跨文化解释智能体把儒家思想放进不同文化语境中解释，避免误读；终端适配智能体按设备调整回答形式，给出详、简、卡片、语音等不同形态；语音交互智能体处理语音提问、朗读经典与多语言语音回答。

典型流程：

```
用户输入 → 总控理解 → 任务分解
  → 经典检索 + 知识图谱
  → 概念解释 + 教学引导
  → 翻译 / 跨文化转化（可选）
  → 候选回答
  → 校验智能体复查
  → 终端适配输出
  → 推荐追问 / 学习路径
```

### 五、前端设计原则

#### 5.1 多终端策略

| 终端 | 主布局 | 信息密度 | 主交互 |
|------|--------|----------|--------|
| 桌面 | 三栏（导航 + 内容 + 依据面板） | 高 | 鼠标 + 键盘 |
| 平板 | 两栏（侧栏可折叠） | 中 | 触控 + 笔 |
| 手机 | 单栏 + 底部 Tab | 低 | 触控 + 语音 |

原型阶段的技术路线是响应式 Web + PWA，一套代码覆盖三端。

#### 5.2 全球化与多语言

界面文案用 i18next / vue-i18n 处理；经典内容由后端按 `lang` 字段返回对应译文；智能体输出经翻译智能体生成。儒家术语统一用三段式，如 `Ren (仁) — humaneness / benevolence`。阿拉伯文等 RTL 语言通过 CSS 逻辑属性适配。

#### 5.3 面向 Z 世代

Z 世代移动原生、注意力碎片化，内容以短为优先，浏览用滑动流；视觉驱动、反长文，信息用卡片、动效、短视频承载；反说教、要共鸣，AI 的定位是"同行者"而不是老师；社交即身份，内容要可分享、可二创、有梗；对游戏化有预期，做打卡、成就、等级、勋章；个性化是基本要求，主题和 AI 人格都能自选；重视情绪与陪伴，整体气质治愈、不评判；偏好暗黑模式，默认提供 Dark / Light / 护眼；作为 AI 原生的一代，不向他们解释 AI，直接给体验。核心设计从「庄重古典 + 学者气质」转向「东方酷感 + 朋友式陪伴 + 轻量游戏化」。

#### 5.4 视觉系统：新东方美学

主色取墨青 `#2C3E50`、朱砂 `#A63A2C`、宣纸 `#F5F0E6`；国潮辅色用故宫红 `#E94F37`、青瓷绿 `#3FA796`、琉璃黄 `#F4C430`、霁蓝 `#1E5F8E`。经典内容用思源宋体，界面用思源黑体，西文用 Inter；图标用 Tabler 线性图标。另以红底白字的方章印章作强调元素。视觉上避免满屏水墨、毛笔字标题和过度敬语。

### 六、核心页面（8 屏）

#### 1. 首页

顶部是带陪伴感的招呼（如"早安，小玥 · 童生 lv.3"）和通知；今日金句卡用大字展示原文与出处，可分享、可一键生成壁纸；中部 2×2 排布四大入口：聊一聊、刷经典、读一读（NEW）、学一学；"经典回应当下"把"我又内耗了""卷不动也躺不平"这类现代痛点接到对应经典上；底部 Tab 固定为首页、刷刷、读经、对话、我。

#### 2. 读一读（经典阅读）

顶部有典籍切换器（论语 · 学而 ▾）和语言切换（中 / EN / 日 / ⋯）；原文、拼音、译文、释义、AI 五类信息的显示与否由用户自由组合。主阅读区分五层：原文用思源宋体大字呈现，重点字词高亮且可点击；拼音为小字斜体；译文支持多语言；字词释义含朱熹注一类的传统注疏；AI 解读以青绿卡片呈现，与传统注释区分。底部动作栏提供朗读、收藏、问 AI、分享，分页器含上一章、章节进度、下一章。

#### 3. 智能对话页

顶部是 AI 人格名片（子曰君等，可一键切换），并有初学者、课堂、研究三种模式。AI 回复自动拆成多条短消息，避免大段文字墙，消息中可嵌入朱砂左边框的经典卡片（原文加出处）；打字中动效之外附推荐追问 chips。输入框支持语音、文字、emoji 与发送。

#### 4. 经典短视频流

TikTok 式全屏暗黑沉浸；中央大字艺术化展示原文，配英文翻译；画面上标注来源 chip 与 AI 人格署名；右侧动作栏有点赞、评论、分享、壁纸、收藏；底部标签用年轻化黑话，如 `#i人友好`。

#### 5. 君子之路（游戏化学习）

顶部段位卡借用科举体系，从童生、秀才、举人、进士到翰林逐级晋升，配进度条；连续打卡用火苗、大字天数和本周七天点阵呈现；礼、乐、射、御、书、数六艺各有圆环进度；今日修行给 3 个微任务，每个标注六艺奖励；最新勋章分金、银、未解锁三种状态，均为印章造型。

#### 6. 概念图鉴

整体沿用 Pokédex 思路，进度形如 `35 / 108 已收`；支持横滑筛选全部、已收、未解锁和按学派；概念带常规 / SR / SSR 稀有度角标；刚解锁的卡片高亮并带新解锁红点；未解锁的卡片灰底、加锁图标并给解锁提示；每个概念同时展示汉字、拼音和英文。

#### 7. 知识图谱

桌面端为全屏交互图谱，用 ECharts / D3 实现，节点分人物、概念、篇章、命题四类，关系边带文字标签；手机端降级为概念瀑布流加关系卡。

#### 8. 个人中心 / 我的书院

头像可装扮成古今混搭的小君子；主题皮肤分基础、节气限定、节日限定；页内汇总学习记录、勋章墙与收藏夹，并同步多设备状态；提供 GDPR / CCPA 数据导出入口。

### 七、关键交互模式

回答默认给精炼结论，可逐层展开到详细解释、经典原文、智能体推理链。AI 人格可自选，内置子曰君、小颜回、庄生、现代小张、诗哥五种风格。引用依据均可点击，直接跳到读经页对应位置。问题模糊时弹出选项卡让用户澄清，而不是给出可能错误的答案；检测到负面情绪词时先共情再回应。游戏化反馈在移动端配合 Haptic 触觉强化。

# 第四篇　后台设计方案

> 配套《平台设计方案》前端（本册第三篇）· 2026-06-05

本文档承接已完成的前端原型（多终端 / 多语言 / 10 类智能体 / 游戏化 8 屏），给出**可落地**的后端设计：服务边界、接口契约、数据模型、智能体编排、RAG 管线、成本与性能、全球部署与合规。

---

### 一、设计原则

所有终端（Web / PWA / 平板 / 小程序 / 语音）共用同一套 API，差异只在「终端适配」这一层做投影，不为某个端单独开后端。可追溯优先是儒家平台的底线：每一条 AI 回答都必须能映射回原文出处（书·篇·章·句），这也是前端「校验徽章」「依据可点击溯源」功能的后端基础。

智能体是手段不是目的。10 类智能体不等于每次请求 10 次 LLM 调用，多数智能体实现为工具/函数或条件分支，只有需要生成与推理的环节才真正起 LLM，目标是常见问答 P95 首字延迟 < 1.5s。

成本上，经典文本是有限且基本不变的语料，应大量预计算、强缓存（语义缓存 + 译文缓存 + 概念解释缓存），把贵的 LLM 调用压到真正需要的地方。部署上，业务服务全部无状态、可横向扩展，状态收敛到数据库与对象存储，便于多区域部署。

### 四、对话编排服务（核心）

这是整个后端的心脏，对应前端「智能体可视化」「分层展开」「校验徽章」。

#### 4.1 编排策略：路由 + 并行扇出 + 单次校验

不要把 10 个智能体串成一条 10 跳的链（慢且贵）。改用如下 LangGraph 状态图：

```
            ┌──────────────┐
   输入 ──▶ │  Router/Planner│  轻量模型：识别意图、语言、所需能力、终端
            └──────┬───────┘
                   │  产出执行计划（需要哪些节点）
        ┌──────────┼───────────────┬──────────────┐
        ▼          ▼               ▼              ▼     （能并行的并行扇出）
   ┌────────┐ ┌─────────┐    ┌──────────┐  ┌──────────┐
   │经典检索 │ │知识图谱 │    │概念解释  │  │教学引导  │
   │(RAG)   │ │(Neo4j) │    │(LLM/缓存)│  │(LLM)    │
   └───┬────┘ └────┬────┘    └────┬─────┘  └────┬─────┘
       └───────────┴──────┬───────┴─────────────┘
                          ▼
                  ┌───────────────┐
                  │  合成 Synthesizer│  旗舰模型：基于检索证据生成候选答案（带引用）
                  └───────┬───────┘
                          ▼
              ┌───────────────────────┐
              │ 翻译 / 跨文化转化（条件） │  非中文用户或显式要求时启用
              └───────────┬───────────┘
                          ▼
                  ┌───────────────┐
                  │  校验 Verifier  │  核对每条主张是否有原文支撑，打三项评分
                  └───────┬───────┘
                          ▼
                  ┌───────────────┐
                  │  终端适配 + 追问 │  按设备投影格式 + 生成推荐追问 chips
                  └───────┬───────┘
                          ▼
                       流式输出
```

图上每个智能体的真实实现形态如下，多数并不起 LLM：

| 智能体 | 实现形态 | 是否起 LLM |
|--------|---------|-----------|
| 总控（Router/Planner） | 轻量 LLM + 规则 | 是（小模型/可缓存） |
| 经典检索 | 向量检索 + 重排函数 | 否（纯检索） |
| 知识图谱 | Cypher 查询函数 | 否 |
| 概念解释 | 缓存命中→直出；未命中→LLM | 多数命中缓存 |
| 教学引导 | LLM（结合用户画像） | 是 |
| 合成/回答 | 旗舰 LLM | 是（主成本） |
| 多语言翻译 | LLM；术语走对照表 | 条件 |
| 跨文化解释 | LLM（带文化语境 prompt 模板） | 条件 |
| 回答校验 | LLM（约束式核对） | 是 |
| 终端适配 | 纯函数（按 device 投影） | 否 |
| 语音 | ASR/TTS 服务 | 否（专用模型） |

一次典型中文问答约 **2–3 次 LLM 调用**（路由小模型 + 合成 + 校验），其余都是检索、缓存和函数；外文跨文化问答再加 1–2 次。

#### 4.2 流式协议

客户端发 `POST /api/v1/chat`，服务端用 SSE（或 WebSocket）流式返回。事件类型分离，前端据此驱动「智能体状态条」「分层展开」「经典卡片」：

```
event: agents      data: {"active":["retrieval","graph","explain"]}   // 点亮智能体色点
event: token       data: {"text":"克己复礼"}                           // 流式正文
event: citation    data: {"book":"论语","chapter":"颜渊","ref":"12.1"} // 经典卡片
event: verify      data: {"textual":0.95,"modern":0.7,"cultural":0.8}  // 校验徽章三评分
event: followups   data: ["礼和仁是什么关系？","现代社会还需要礼吗？"]    // 追问 chips
event: done        data: {"message_id":"...","tokens":1234}
```

#### 4.3 RAG 检索细节

1. 混合检索：向量召回（语义）加关键词/BM25（精确术语如人名、篇名）加图谱召回（概念关联），三路融合。
2. 重排：用 reranker（或轻量 LLM）给候选句排序，取 Top-K（K≈5）。
3. 证据绑定：合成节点的 prompt 强制「只能基于提供的证据作答，每个论断标注 `[出处编号]`」，校验节点再核对编号是否真实存在，这是降幻觉的关键。
4. 多语言检索：用户问英文，就用多语种 embedding 在同一向量空间召回中文原文，译文从译文库取，不现翻原文。

### 五、数据模型

#### 5.1 经典内容（PostgreSQL）

核心是把「书→篇→章→句」做成可寻址的树，每个节点带稳定 `ref_id`（如 `lunyu.yanyuan.12.1`），这是全平台溯源的主键。

```sql
-- 典籍
CREATE TABLE books (
  id            TEXT PRIMARY KEY,        -- 'lunyu'
  title_zh      TEXT NOT NULL,           -- '论语'
  title_i18n    JSONB,                   -- {"en":"The Analects","ja":"論語"}
  author        TEXT,                    -- '孔子及弟子'
  era           TEXT,
  sort_order    INT
);

-- 章节（篇）
CREATE TABLE chapters (
  id            TEXT PRIMARY KEY,        -- 'lunyu.yanyuan'
  book_id       TEXT REFERENCES books(id),
  title_zh      TEXT,                    -- '颜渊'
  title_i18n    JSONB,
  sort_order    INT
);

-- 句/段（最小可寻址单元，对应前端"读一读"的五层信息）
CREATE TABLE passages (
  id            TEXT PRIMARY KEY,        -- 'lunyu.yanyuan.12.1'
  chapter_id    TEXT REFERENCES chapters(id),
  ref_label     TEXT,                    -- '论语·颜渊·12.1'
  original_text TEXT NOT NULL,           -- '克己复礼为仁。'
  pinyin        TEXT,                    -- 'kè jǐ fù lǐ wéi rén'
  sort_order    INT,
  concepts      TEXT[],                  -- ['ren','li'] 关联概念
  meta          JSONB
);

-- 译文（多语言，一句多译）
CREATE TABLE translations (
  passage_id    TEXT REFERENCES passages(id),
  lang          TEXT,                    -- 'en','ja','ko'...
  text          TEXT,
  translator    TEXT,                    -- 来源/译者，可信度溯源
  PRIMARY KEY (passage_id, lang, translator)
);

-- 注释（传统注疏 + 现代释义，对应"字词释义"层）
CREATE TABLE annotations (
  id            BIGSERIAL PRIMARY KEY,
  passage_id    TEXT REFERENCES passages(id),
  type          TEXT,                    -- 'classical'(朱熹注) | 'modern' | 'word'
  lang          TEXT,
  source        TEXT,                    -- '朱熹《论语集注》'
  content       TEXT
);

-- 概念本体（对应"概念图鉴"，跨语言术语对照）
CREATE TABLE concepts (
  id            TEXT PRIMARY KEY,        -- 'ren'
  zh            TEXT,                    -- '仁'
  pinyin        TEXT,                    -- 'rén'
  i18n          JSONB,                   -- {"en":"benevolence / humaneness","ja":"仁"}
  school        TEXT,                    -- 学派
  rarity        TEXT,                    -- 'normal'|'SR'|'SSR'（图鉴稀有度）
  definition    JSONB,                   -- 多语言释义
  related       TEXT[]                   -- 相关概念
);
```

AI 解读（第五层）不入库为静态文本，而是运行时由概念解释/合成智能体生成并缓存，避免把"AI 发挥"混进权威经典。

#### 5.2 向量库（Milvus / Chroma）

每个 passage、annotation、concept 切分后入向量库，元数据携带 `ref_id` 便于回链：

```
collection: confucian_corpus
  vector:   embedding (multilingual, 1024d)
  fields:   ref_id, type(passage|annotation|concept), book_id, lang, text
```

#### 5.3 知识图谱（Neo4j）

```
节点：(:Person {id,name})       人物：孔子、颜渊、孟子...
      (:Concept {id,zh,en})     概念：仁、礼、中庸...
      (:Passage {id,ref})       篇章/句
      (:Proposition {id,text})  命题：'克己复礼为仁'
      (:School {id,name})       学派

关系：(:Person)-[:DISCIPLE_OF]->(:Person)
      (:Concept)-[:RELATED_TO {label}]->(:Concept)
      (:Passage)-[:MENTIONS]->(:Concept)
      (:Person)-[:PROPOSED]->(:Proposition)
      (:Proposition)-[:ABOUT]->(:Concept)
```

图谱服务对外提供三类查询：概念邻域子图（前端图谱页）、两节点间路径（"仁和礼怎么连"）、人物关系网。

#### 5.4 用户与游戏化（PostgreSQL + Redis）

```sql
users(id, email, oauth_provider, created_at, ...)
user_profiles(user_id, lang, theme, ai_persona, level, level_name,  -- 童生/秀才...
              learning_stage, interests JSONB, locale, consent JSONB)
user_progress(user_id, streak_days, last_checkin, liuyi JSONB,       -- 六艺进度
              total_xp)
badges(id, name, tier, criteria)                                     -- 勋章定义
user_badges(user_id, badge_id, unlocked_at)
concept_collection(user_id, concept_id, unlocked_at)                 -- 图鉴收集
favorites(user_id, target_type, target_ref, created_at)             -- 收藏(句/卡片/视频)
conversations(id, user_id, created_at, mode)                        -- 对话会话
messages(id, conversation_id, role, content, citations JSONB,
         verify_scores JSONB, agents_used TEXT[], created_at)
```

Redis 这边承载四件事：连续打卡计数、排行榜（ZSET）、会话上下文短缓存、限流计数。

```
POST /voice/tts      ({ref_id|text, lang, voice}) # 经典朗读/播报 → 音频URL

# 用户
POST /auth/login  /auth/oauth/{provider}  /auth/refresh
GET/PUT /me/profile                               # 含语言/主题/AI人格
GET  /me/export                                   # GDPR/CCPA 数据导出
DELETE /me                                         # 账户与数据删除
POST /sync                                         # 多设备同步
```

### 七、多语言与跨文化（后端职责）

界面文案与内容分离：界面 i18n 在前端；经典内容译文由后端从 `translations` 表按 `lang` 返回，权威译本优先，缺失时才由翻译智能体兜底生成并标注「AI 译」。

术语上，所有儒家核心概念走 `concepts.i18n` 统一对照表，保证全平台「仁」始终呈现为 `Ren (仁) — humaneness / benevolence`，不让 LLM 每次自由发挥译法。

跨文化解释智能体用结构化 prompt 模板而非自由发挥，固定输出框架：古义 → 与社会秩序的关系 → 与自我修养的关系 → 与现代观念的差异 → 可现代转化/不可照搬的边界，对应方案中 "Is Li just social control?" 的标准回答骨架。

价值边界上，跨文化和校验节点对涉及现代价值冲突的问题做「平衡说明」，再由内容审核（见第十节）兜底。

---

### 八、成本、性能与缓存

经典语料有限且稳定，这是最大的优化杠杆，缓存分五层：

| 缓存层 | 内容 | 失效策略 |
|--------|------|----------|
| CDN 边缘 | 原文/拼音/译文/TTS 音频/图片 | 内容版本号变更才失效（近乎永久） |
| 概念解释缓存 | 每个概念在每种语言/模式下的标准解读 | 离线预生成 + 人工审核后冻结 |
| 语义缓存（Redis） | 「相似问题→已审答案」 | 向量相似度 > 阈值命中，TTL + 人工置顶 |
| 译文缓存 | AI 兜底译文 | 长期，待权威译本补入后替换 |
| TTS 预生成 | 高频经典句的多语言音频 | 离线批量，存对象存储 |

模型分级：路由、分类、翻译用轻量模型，合成和校验用旗舰模型，LLM 网关按 `task_type` 路由。上线前再离线预计算一遍——每条 passage 的 AI 解读、每个概念的标准解释、高频追问——把热路径变成查表。目标是缓存命中类问答几乎零 LLM 成本、亚秒响应，只有真正新颖或个性化的问题才走完整智能体链。

---

### 九、语料治理与导入管线

数据质量等于平台可信度。建议一条独立的离线管线（Celery 任务）：

```
原始文本（古籍/译本/注疏）
  → 清洗 + 结构化（书/篇/章/句切分，生成 ref_id）
  → 校对（人工抽检，权威版本对齐）
  → 拼音标注 + 概念标注（NER + 人工核对）
  → 多语种向量化 → 入 Milvus
  → 抽取人物/概念/命题/关系 → 入 Neo4j
  → 离线预生成 AI 解读/概念解释 → 人工审核 → 缓存冻结
  → 版本号 +1，灰度发布
```

关键是经典原文与权威译注由人把关入库，AI 只负责「解读层」，且明确标注、可校验。这是与普通 RAG 玩具的本质区别。

### 十、安全、合规与审核

| 维度 | 措施 |
|------|------|
| 认证 | JWT + Refresh Token，OAuth（Google/Apple/微信） |
| 传输/存储 | 全链路 TLS，敏感字段加密，密钥走 KMS |
| 限流 | 网关按用户/IP 限流，LLM 调用单独配额防滥用 |
| GDPR/CCPA | `/me/export` 数据导出、`DELETE /me` 删除权、同意管理 `consent` |
| 数据驻留 | 多区域部署，欧盟用户数据留欧盟节点 |
| 日志脱敏 | 日志中 PII 脱敏，问答日志与身份分离存储 |
| 内容审核 | 输入/输出双向审核；多语言敏感内容过滤；涉政/价值冲突走平衡说明模板 |
| 提示注入防护 | 用户输入与系统 prompt 隔离，检索证据不可覆盖系统指令 |

### 十一、可观测与评估

链路追踪用 OpenTelemetry 贯穿网关、编排和各智能体；Langfuse 记录每次 LLM 调用的 prompt、输出、Token、延迟和成本。

质量评估先建多语言评测集（问题→期望出处/要点），再离线回归加在线抽样打分，维度包括忠实度、出处正确率、幻觉率、跨文化恰当性，这是前端「校验徽章」的线下保障。

业务指标看 DAU、连击留存、概念收集率、追问点击率、各语言占比、各终端占比；告警盯幻觉率、出处错误率、P95 延迟和 LLM 成本异常。

### 十二、部署拓扑（全球）

```
用户 → Anycast/GeoDNS → 就近区域
   区域内：CDN → API Gateway → K8s 服务（无状态，HPA 弹性）
   数据：主区域 PostgreSQL（多区域只读副本）、Milvus、Neo4j
        Redis 区域内、对象存储跨区域复制
   LLM：按区域选可用模型服务端点（合规 + 低延迟）
```

无状态服务做区域多活；强一致数据（用户/订单）单主多副本；经典内容只读、可全区域复制。发布走蓝绿/灰度，语料版本与服务版本解耦。

### 十四、后端创新点（呼应前端）

证据绑定加校验闭环：每条回答的论断都绑定 `ref_id`，校验节点核对真实性并产出三项评分，把"可追溯/可校验"做成系统机制而非口号。

路由式智能体编排：动态规划只激活必要的智能体，再并行扇出，"多智能体协同"的表达力和亚秒级体验可以兼得。

经典语料的预计算与冻结：把有限稳定的经典内容大规模预生成，经人工审核后永久缓存，高质量与低成本同时拿到。

权威分层：原文和译注由人把关，AI 解读可校验、明确标注，两层分开存，杜绝"AI 发挥污染经典"。

统一术语本体：跨语言概念对照表保证全平台、全语种术语一致，避免 LLM 自由译法造成的文化误读。

多端单后端：终端差异收敛到「终端适配」投影层，一套 API 服务全部终端。
