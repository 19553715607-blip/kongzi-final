# 第 1 章 需求分析

## 1.1 项目背景与问题定义

### 1.1.1 题目来源

作品名称取自《论语·子张》：“博学而笃志，切问而近思，仁在其中矣。”本作品将“切问”理解为对解释依据的追问，将“近思”理解为把义理放回具体情境中的思考和实践。

作品不试图构造一个替孔子发言的数字人格，也不以模型参数量或“智能体数量”为主要贡献。作品关注的是：当大模型已经能够流畅讲述经典时，学习者如何知道一条解释来自哪里、属于哪一层解释，以及怎样将抽象义理转化为可反思的行为学习。

### 1.1.2 儒家经典智能学习的三重断裂

当前产品通常能够生成流畅答案，却仍存在三重断裂。

| 断裂 | 典型表现 | 学习风险 | 本作品回应 |
|------|----------|----------|------------|
| 答案与出处断裂 | 编造篇名、错引原文、只给出书名而无具体章句 | 学习者无法判断“这句话从哪里来” | 可溯源 |
| 原义与阐释断裂 | 将经典原义、历代注疏、现代价值和跨语翻译混成一段 | 学习者无法判断“这句话凭什么成立” | 可核验 |
| 知识与实践断裂 | 能解释“礼”，却不能在迎宾、揖让、安席中判断过与不及 | 学习停留在概念记忆，不能形成情境判断 | 可演练 |

项目的核心问题因此表述为：

> 在大模型能够流畅谈论儒家经典的前提下，如何让每条关键解释能够回到出处、区分解释边界并接受核验，同时让经典义理进入可以操作、犯错和复盘的情境学习？

### 1.1.3 三项核心价值的可验收定义

| 核心价值 | 系统定义 | 用户可见结果 | 主要验收指标 |
|----------|----------|--------------|--------------|
| 可溯源 | 每条关键论断绑定具体原文、注疏或译本及其证据片段 | 点击论断跳到书、篇、章句和对应文本 | 引用精确率、引用覆盖率、错引率 |
| 可核验 | 区分原义转述、注疏解释、现代发挥和术语说明，并判断证据是否支持论断 | 显示论断类型、证据、支持状态和必要警示 | 论断支持 F1、无依据论断率、分轨分类 F1 |
| 可演练 | 将有出处的义理转化为可操作、可犯错、可反馈、可复盘的情境 | 行为产生有规则依据的即时反馈和复盘入口 | 规则覆盖率、状态机通过率、学习前后测 |

三项价值不是三个宣传标签，而是需求、实现和测试的共同索引。不能由现场功能或实验数据证明的能力，不写入最终参赛主张。

### 1.1.4 项目背景与边界

中华优秀传统文化的创造性转化、创新性发展及国际传播，是本作品的应用背景。相关课题或政策只能说明需求来源，不能替代作品的技术贡献和用户证据。

本作品聚焦《论语》及与核心概念直接相关的有限经典、注疏和译本。参赛阶段优先保证语料版本清楚、来源合规、专家复核和引用稳定，不以未经审核的语料规模作为成果。

### 1.1.5 政策与课题背景

近三年国家持续强化中华优秀传统文化的创造性转化、创新性发展，以及国际传播能力建设。与本作品直接相关的公开部署包括：

- 2023 年文化传承发展座谈会：建设中华民族现代文明，强调融通中外、贯通古今。
- 2023 年 10 月全国宣传思想文化工作会议提出的「七个着力」：赓续中华文脉、推动两创；加强国际传播能力建设、促进文明交流互鉴。
- 2024 年党的二十届三中全会《决定》：全面提升国际传播效能，建设全球文明倡议践行机制。
- 2025 年国办发〔2025〕4 号：支持文化科技融合、文化领域大模型与数字文化国际化。
- 2026 年 1 月教育部等七部门（含中央宣传部）《关于深入推进中华优秀语言文化传承发展 提高全民语言文化素养的意见》：数字赋能、推广传播、交流互鉴。

更早但仍作总依据的，是 2017 年中办、国办《关于实施中华优秀传统文化传承发展工程的意见》（支持中华典籍走出去、国际汉学交流），以及 2021 年教育部《中华优秀传统文化进中小学课程教材指南》（《论语》等进入课程教材）。

政策用语是中华优秀传统文化、中华典籍、国际传播，而不是单独的「儒家传播条例」。儒家思想是其中明确的思想资源。本团队工作依托中宣部相关课题，需求是可演示、可核对、可练习的交互系统，而不是宣传页或到达率报表。课题是需求来源，不是技术贡献本身。

1. 访谈 10—15 名汉语国际教育教师；

3. 与不少于 3 个真实课堂、社团或教学单位开展试用；
4. 比较直接大模型、普通 RAG 与本作品三种学习方式；
5. 进行前测、后测和条件允许时的 7 天延迟测；
6. 保留匿名化原始记录、知情同意和统计过程。

以上数量是项目目标，不是现有成果。未完成前不得在作品介绍中写成既有用户规模。

## 1.3 核心能力与功能范围

### 1.3.1 可溯源：从论断回到出处

1. 用户以中文或英文提问；
2. 系统召回原文、注疏、译文及必要的图谱路径；
3. 生成结果拆分为若干关键论断；
4. 每条论断绑定实际使用的证据，而不是绑定所有召回结果；
5. 用户点击论断进入相应章句和证据片段；
6. 若关系问题使用图谱，展示最短必要证据路径及其来源。

### 1.3.2 可核验：让解释层次和证据状态可见

答案采用结构化呈现：

- **经**：有直接经典依据的原义转述；
- **注**：有明确作者、书目或研究来源的解释；
- **用**：面向现代生活的引申，必须标为现代发挥；
- **译**：跨语言术语说明，不宣称单一译法穷尽原概念；
- **核验状态**：支持、部分支持、无依据、冲突或存在争议。

系统不使用无法解释的固定“文化分”或“发挥分”。数值置信度只在完成校准实验后用于内部排序，对用户优先展示证据和离散状态。

### 1.3.3 可演练：仪礼情境中的操作与复盘

参赛主演练聚焦“礼·宾至如归”：

1. 用户在浏览器三维情境中完成迎宾、揖让、安席和席间照应；
2. 状态机判断对象次序、行为程度、位置关系和事件时机；
3. 过与不及产生不同反馈；
4. 用户可查看规则的文献来源、适用时代和教学抽象说明；
5. 演练结束后回到相关章句和概念，形成复盘；
6. 用户再次演练，比较前后差异。

### 1.3.4 学习档案

学习档案只服务核心闭环，记录已读出处、易错概念、核验提示和演练记录。是否用演练短板自动调整下一轮检索，需要经过用户实验验证；未验证前只提供可关闭的学习建议，不声称为有效创新。

### 1.3.5 扩展功能

乐、射、御、书、数，完整知识图谱浏览、开放 API、机构后台和运营页面均作为扩展功能。它们可以展示已有工作量，但不进入十分钟答辩主线，也不占用核心实验资源。

## 1.4 同类产品与赛事作品分析

| 类型 | 已解决问题 | 仍存在的缺口 | 本作品的响应 |
|------|------------|--------------|----------------|
| 通用大模型问答 | 低门槛、表达流畅、多语言 | 引用可能错误，原义与发挥混合 | 论断级出处和分轨核验 |
| 古籍大模型或经典智能体 | 古籍处理、领域知识和角色化交互 | 不一定展示论断与证据映射 | 让依据和解释边界成为用户界面 |
| 数字人文知识图谱 | 人物、篇章、概念关系浏览 | 图谱常停留在可视化或槽位查询 | 将带来源图路径并入问答证据 |
| 六艺、VR 与文化互动 | 沉浸体验和文化传播 | 行为规则与经典出处可能脱节 | 规则出处、状态机和学习复盘 |
| 文化类赛事软件 | 文化展示、识别、学习和互动 | 容易形成内容门户或功能拼盘 | 用三项可验证能力收束主线 |

历届高等级软件作品通常同时具备明确问题、完整实现、可演示闭环和可证明的技术或应用增益。本作品不以“首次和孔子聊天”“首次使用知识图谱”作为创新主张。

## 1.5 成功标准与项目边界

### 1.5.1 参赛成功标准

最终版本必须同时满足：

1. 三项核心价值均能通过现场功能和测试证明；
2. 至少两项核心方法完成基线和消融实验；
3. 仪礼规则具有来源和教学抽象说明；
4. 具有真实教师或学习者试用证据；
5. 公网版本与离线兜底均可稳定演示；
6. 参赛作者、作品周期、知识产权和数据来源符合当届规程。

### 1.5.2 明确不做

- 不训练或宣称拥有“儒家通用大模型”；
- 不把智能体数量当作创新；
- 不用种子数据冒充真实用户；
- 不用未经校准的固定分数表示文化正确性；
- 不将教学阈值包装成历史事实；
- 不在核心完成前继续扩张六艺、社交和机构功能。

# 第 2 章 概要设计

## 2.1 系统总体设计

系统采用 B/S 架构，由浏览器端、应用服务、证据与规则服务、数据层和模型层组成。

```text
用户浏览器
  ├── 切问：提问、论断卡、证据卡、出处阅读
  ├── 近思：仪礼情境、即时反馈、规则出处、复盘
  └── 学习档案：已读出处、易错概念、演练记录
          │ HTTPS / SSE
应用服务
  ├── 查询分类与对话编排
  ├── 论断生成与分轨
  ├── 论断—证据核验
  ├── 仪礼状态机
  └── 用户与学习记录
          │
证据与规则服务
  ├── 文本检索与重排
  ├── 带来源的图谱路径
  ├── 术语与译法表
  └── 仪礼规则库
          │
数据层
  ├── 经典、注疏、译文与来源
  ├── 概念、关系与证据路径
  ├── 论断、核验和会话记录
  └── 演练规则、事件与结果
          │
模型层
  ├── 多语言向量模型
  ├── 生成模型
  ├── 重排或论断支持模型
  └── 离线或 Mock 兜底
```

系统原则是“证据先行、生成受约束、结果可回放、失败可见”。模型可替换，但 `ref_id`、论断结构、证据状态和仪礼规则保持稳定。

## 2.2 三条核心技术链

### 2.2.1 可溯源链

```text
问题分类
  → 文本候选召回
  → 必要时取得图谱路径
  → 按原文 / 注疏 / 译文 / 图关系分型
  → 重排并生成证据束
  → 生成论断
  → 记录每条论断实际使用的证据
```

### 2.2.2 可核验链

```text
回答草稿
  → 论断切分
  → 经 / 注 / 用 / 译分类
  → 论断—证据支持判断
  → 术语和引用一致性检查
  → 无依据论断拦截或降级
  → 输出可读核验状态
```

### 2.2.3 可演练链

```text
载入情境与规则版本
  → 用户执行迎宾 / 揖让 / 安席 / 照应
  → 状态机判断转移是否合法
  → 输出过 / 不及 / 合宜及其原因
  → 显示规则出处和教学抽象
  → 保存复盘并跳回相关章句
```

# 第 3 章 详细设计

## 3.1 界面与交互设计

### 3.1.1 主演示路径

界面围绕“一问、一验、一礼”设计：

1. 首页只突出“开始切问”和“进入近思”；
2. 用户提出一个概念或章句问题；
3. 回答区按论断显示类型、支持状态和证据编号；
4. 证据区显示原文、出处、证据片段和来源类型；
5. 用户点击进入章句阅读；
6. 从相关概念进入仪礼情境；
7. 用户故意或自然犯错，查看规则依据并重新完成；
8. 演练后进入复盘。

### 3.1.2 视觉语义

| 视觉 | 含义 |
|------|------|
| 墨色 | 经典原文和直接原义 |
| 深蓝 | 注疏或现代学术解释 |
| 朱砂 | 现代发挥和应用 |
| 金棕 | 译法、术语差异和文化说明 |
| 灰色警示 | 依据不足、存在争议或系统拒答 |

论断编号与证据编号使用相同颜色或连线。视觉重点是让评委一眼看出“哪句话由哪条证据支持”，水墨装饰不得影响信息层级和可读性。

### 3.1.3 核验状态呈现

用户界面优先显示离散状态：

- 有直接依据；
- 有间接依据；
- 部分支持；
- 无直接依据；
- 与证据冲突；
- 存在不同解释。

在论断核验完成校准前，不显示看似精确的“文化分”“发挥分”。内部置信度不得直接等同于文化正确性。

### 3.1.4 视觉方向与多端适配

界面采用「经折对读」：宣纸底、宋体标题、克制朱砂，不做满屏水墨或通用卡片墙。首页只保留「开始切问 / 进入近思」两门。导航收敛为切问、近思、我；读经与图谱收入「典」。

| 终端 | 布局 |
|------|------|
| 电脑 | 左右开页：左叶论断，右叶证据；选中后编号与描边对位 |
| 平板 | 主栏论断，证据以右侧抽屉打开 |
| 手机 | 底栏三入口；点论断后证据自底部上滑 |

颜色、字号、分轨语义写成同一套 token，后续 App / 小程序沿用，不另起视觉系统。高保真界面稿见 `/design`。

## 3.2 数据模型与语料治理

### 3.2.1 经典与证据实体

| 实体 | 关键字段 |
|------|----------|
| `works` | 书名、版本、出版或来源信息、许可状态 |
| `chapters` | 所属书、篇名、篇序 |
| `passages` | `ref_id`、原文、章句位置、版本 |
| `annotations` | 注者、时代、书目、文本、许可、审核状态 |
| `translations` | 语言、译者、版本、文本、许可、适用说明 |
| `concepts` | 概念、异名、定义、术语说明 |
| `graph_edges` | 起点、终点、关系、来源、证据片段、审核状态 |

### 3.2.2 论断与核验实体

每条输出论断至少包含：

```text
claim_id
claim_text
track: jing | zhu | yong | yi
evidence_refs[]
evidence_spans[]
support_status
verifier_version
review_status
```

系统只将回答中实际使用的证据写入 `evidence_refs`，不能把全部 Top-k 召回结果都当成最终引用。

### 3.2.3 仪礼规则实体

每条规则至少包含：

```text
rule_id
action
condition
expected_range_or_order
feedback_over
feedback_under
source_ref
source_excerpt
era
applicable_scene
abstraction_note
expert_review_status
rule_version
```

无法找到直接史料依据但为了教学交互设置的阈值，必须填写 `abstraction_note`，说明它是教学抽象而非历史测量结果。

### 3.2.4 语料治理流程

```text
确定版本与许可
  → 文本清洗与章句切分
  → 建立 ref_id
  → 添加注疏、译文和来源
  → 概念与关系标注
  → 双人抽样复核
  → 冲突处理
  → 发布语料版本
  → 构建索引
```

最终文档需附数据卡，说明覆盖范围、版本、许可、标注者、审核比例、已知偏差和不支持的问题类型。

## 3.3 关键技术设计

### 3.3.1 可寻址证据与证据片段

`ref_id` 贯穿检索、生成、核验、阅读和演练规则。句是默认引用单位；当一句过长或包含多个命题时，增加稳定的片段定位信息。模型不得生成不存在的篇名或 `ref_id`。

### 3.3.2 经—注—用分轨的论断生成

生成过程分为两步：先基于证据产生结构化论断，再渲染为自然语言。不同轨道采用不同约束：

- 经轨必须绑定经典原文；
- 注轨必须绑定具体注者、书目或学术来源；
- 用轨允许现代应用，但必须显式标记；
- 译轨展示译法和解释边界，不给出脱离语境的唯一等价词；
- 无足够证据时输出澄清问题或有限拒答。

分轨准确性必须通过人工标注数据评测，不能只依赖提示词自我声明。

### 3.3.3 图文协同的可溯源检索

查询先分类为单句释义、注疏辨析、概念关系、跨篇章比较或不可回答。不同问题使用不同检索策略：

- 单句释义：文本向量召回、关键词召回和重排；
- 注疏辨析：按来源类型过滤并保留作者与时代；
- 概念关系：文本证据与带来源图路径联合；
- 跨篇章比较：分别召回各概念证据后再组织关系；
- 不可回答：检索置信不足时进入拒答或澄清。

融合权重由开发集调优或学习排序确定。不得只在文档中给出未经验证的固定公式。最终通过消融实验判断图谱、来源类型和重排器各自的贡献。

### 3.3.4 论断—证据核验

核验器对每条论断和证据片段输出：支持、部分支持、无依据、冲突或存在争议。核验流程包括：

1. 引用合法性检查；
2. 论断与证据片段对齐；
3. 支持关系判断；
4. 经、注、用、译分类检查；
5. 现代发挥漏标检查；
6. 关键术语一致性检查；
7. 无依据论断拦截或降级；
8. 保存核验器版本以便回放。

核验器可以由规则、自然语言推断模型和受约束大模型组合实现，但必须在独立测试集上报告结果，并接受人工错误分析。

### 3.3.5 跨语术语与解释边界

参赛主版本先保证中文和英文质量。法语、西班牙语和阿拉伯语只在获得合格语料及审核后加入正式能力列表。

“仁”“礼”“义”“恕”等核心概念保留汉字和拼音，并提供多个常见译法、译者或版本及使用说明。例如，系统不简单判定 *benevolence* 必然错误，而说明它可能覆盖“仁”的部分含义，但不能在所有语境中穷尽该概念。

### 3.3.6 基于规则出处的仪礼状态机

仪礼情境的状态至少包括：宾客集合、身份关系、当前对象、席位映射、操作序列、时间线和规则版本。每次状态转移同时记录行为、上下文、命中规则和反馈。

评价维度可保留敬、序、节，但其含义必须具体化：

- **敬**：行为程度是否合宜，是否出现轻慢或过恭；
- **序**：迎宾顺序和席位关系是否一致；
- **节**：行为时机和频率是否适当，是否过度殷勤。

几何平均只作为防止单项偏废的聚合方式，不单独宣称数学创新。需要报告零值处理、权重、阈值敏感性及其教学理由。

### 3.3.7 学习复盘与状态建议

系统记录用户查看过的证据、出现过的核验警示和仪礼错误。初期只生成可解释的复盘建议，例如：

- 查看与“宾主有序”相关的章句；
- 比较“敬”与“谄”的不同；
- 重新完成发生失序的情境。

自动改变下一轮检索或练习难度属于待验证功能。只有在用户实验中产生稳定增益，才纳入最终创新表述。

## 3.4 接口设计

| 能力 | 接口示例 | 主要返回 |
|------|----------|----------|
| 切问 | `POST /api/v1/chat` | 论断、轨道、证据、核验状态、后续建议 |
| 出处阅读 | `GET /api/v1/passages/{ref_id}` | 原文、注疏、译文、来源和版本 |

具体字段以 OpenAPI 文档为准。参赛前需保存一份与冻结版本一致的接口快照。

# 第 4 章 测试与评测方案

## 4.1 评测目标与当前状态

本章规定参赛版本必须完成的评测协议。当前已有少量检索样例和交互脚本，但不足以支持正式结论。所有结果表在实验完成后填写，未完成前不得使用占位数字。

评测回答四个问题：

1. 系统能否找到正确且实际使用的证据？
2. 系统能否正确判断论断是否受到证据支持？
3. 图谱、分轨和核验分别带来多少增益？
4. 仪礼情境是否稳定、规则是否有据、是否改善学习？

## 4.2 专家标注评测集

### 4.2.1 目标规模

建立不少于 600 道问题的独立评测集：

| 类型 | 目标数量 | 主要能力 |
|------|----------|----------|
| 单句释义 | 180 | 文本检索、原义转述、引用 |
| 注疏与解释辨析 | 120 | 来源类型、不同解释和争议 |
| 概念多跳与跨篇章比较 | 150 | 图文协同检索、关系证据 |
| 错引、错时代、错格义、不可回答 | 150 | 核验、拒答、术语边界 |
| 合计 | 600 | — |

第一阶段重点建设中文和英文。题目来源包括教师命题、学习者真实问题、同类系统失败案例和对抗构造。测试集在定稿后封存，不能用于逐题调参。

### 4.2.2 标注内容

每题至少标注：

- 问题类型；
- 期望证据及证据片段；
- 可接受的核心论断；
- 不可接受或常见错误；
- 经、注、用、译轨道；
- 是否应拒答或澄清；
- 核心术语说明；
- 难度和语言。

### 4.2.3 标注质量

由至少两名具备相关背景的标注者对部分数据独立标注，报告一致性和分歧处理流程。领域专家负责标注手册、疑难案例和最终仲裁。作品文档附标注者背景、审核比例、数据版本和已知局限。

## 4.3 基线与消融实验

### 4.3.1 比较系统

| 编号 | 系统 |
|------|------|
| B0 | 直接调用同一生成模型，不提供外部证据 |
| B1 | 普通向量 RAG |
| B2 | 向量 RAG + 重排 |
| B3 | 分型文本证据，不使用图谱 |
| B4 | 图文协同证据，不使用论断核验 |
| Ours | 图文证据 + 分轨生成 + 论断核验 |

所有系统使用相同底座模型、相同测试集和尽量一致的生成预算，避免通过更大模型混淆方法贡献。

### 4.3.2 消融项目

- 移除图谱证据；
- 移除来源类型；
- 移除重排器；
- 移除经—注—用分轨；
- 移除论断拦截；
- 取消术语说明；
- 关闭演练后的复盘建议。

如果某个模块不能产生可重复增益，应降级为工程特色或删除，不能继续保留为核心创新。

## 4.4 可溯源评测

| 指标 | 含义 |
|------|------|
| Recall@k | 期望证据是否进入前 k 条召回结果 |
| MRR / nDCG | 正确证据在排序中的位置质量 |
| 引用精确率 | 输出引用中真正支持相应论断的比例 |
| 引用覆盖率 | 需要证据的关键论断中已绑定有效证据的比例 |
| 错引率 | 篇名、章句、文本或来源错误的比例 |
| 多跳路径正确率 | 图谱路径的节点、关系和来源是否正确 |

测试不能只检查“检索到了相关句子”，还必须检查答案中的论断是否真正使用了该证据。

## 4.5 可核验评测

| 指标 | 含义 |
|------|------|
| 论断支持 Precision / Recall / F1 | 支持状态判断是否正确 |
| 分轨分类 F1 | 经、注、用、译分类是否正确 |
| 无依据论断率 | 无证据支持却以确定语气输出的论断比例 |
| 拒答准确率 | 证据不足时是否正确拒答，证据充分时是否避免误拒答 |
| 现代发挥漏标率 | 当代引申是否被错误包装为经典原义 |
| 术语一致率 | 核心概念在跨语回答中的保留和说明是否符合规范 |

除自动指标外，抽取固定数量回答进行专家盲评，评价经典准确性、解释边界、跨文化清晰度和整体可用性。

## 4.6 可演练评测

### 4.6.1 状态机与规则测试

每条规则至少具有：正例、过例、不及例、边界例和冲突例。测试包括：

- 迎宾次序的所有关键排列；
- 揖让程度的边界与异常输入；
- 席位映射的一致性；
- 时机和频率的边界；
- 重复操作、跳步和中断恢复；
- 规则版本升级后的回归；
- 客户端异常数据的服务端校验。

### 4.6.2 规则学术审核

报告规则来源覆盖率、专家审核比例、存在争议的规则数量和教学抽象比例。存在不同历史解释时，系统应显示适用范围或争议，不将一个实现版本宣布为唯一正确礼制。

### 4.6.3 学习效果

通过情境判断题和迁移任务比较演练前后变化，不能只报告游戏得分或停留时长。重点考察学习者能否识别过与不及、解释错误原因并关联到相关章句。

## 4.7 用户研究

计划设置三种条件：

1. 直接使用通用大模型；
2. 使用普通 RAG 问答；
3. 使用完整的《切问近思》。

测量内容包括：

- 任务完成率和完成时间；
- 出处查找正确率；
- 原义与现代发挥辨析；
- 核心概念理解；
- 仪礼情境判断；
- 即时后测和条件允许时的延迟测；
- SUS 可用性和教师访谈。

若“切问—近思状态建议”未带来稳定学习增益，则从创新点中删除，仅保留为可关闭的推荐功能。

## 4.8 工程测试与发布门槛

### 4.8.1 自动化测试

- 后端单元测试：检索、论断结构、核验、规则和鉴权；
- 后端集成测试：数据库、向量库、图服务、模型超时和降级；
- 前端组件测试：论断卡、证据卡、警示和演练反馈；
- 端到端测试：完整“一问、一验、一礼”；
- CI：每次提交自动执行测试、构建和基础安全检查。

### 4.8.2 性能与故障测试

- P50 / P95 首字延迟和完整回答延迟；
- 典型并发下的错误率；
- 模型接口超时、限流和返回格式异常；
- 图服务不可用时降级为文本证据；
- 向量库不可用时降级为关键词检索；
- 现场断网时使用冻结证据和本地演示路径；
- 长时间运行、浏览器刷新和会话恢复。

### 4.8.3 参赛发布门槛

正式提交前必须满足：

1. 主演示路径端到端测试全部通过；
2. 核心实验可从冻结代码和数据复现；
3. 公网地址连续稳定运行；
4. 源码中不存在真实密钥、默认口令和不应公开的内网信息；
5. 依赖、字体、图片、音频、模型和语料许可完成清单化审查；
6. 作品名称、软著名称、文档、视频和界面保持一致。

## 5.3 用户使用流程

```text
游客进入首页

  → 阅读经 / 注 / 用 / 译论断
```

## 5.4 “一问、一验、一礼”典型演示

### 5.4.1 一问

固定演示问题：

> Is *ren* simply equivalent to benevolence?

或：

> “仁”能不能直接翻译成 benevolence？孔子对“仁”有没有统一定义？

该问题需要检索多个章句，并展示单一译词不能穷尽不同语境中的概念含义。

### 5.4.2 一验

系统展示：

1. 有直接出处的经典论断；
2. 有作者和来源的注疏或学术解释；
3. 明确标出的现代发挥；
4. “仁”的常见译法及解释边界；
5. “仁—礼”关系的必要证据路径；
6. 每条论断的支持状态和可点击证据。

演示重点不是答案篇幅，而是让评委看见“哪句话由哪条证据支持”。

### 5.4.3 一礼

从“仁—礼”关系进入“宾至如归”情境：

1. 故意对尊者揖得过浅，触发“失之轻慢”；
2. 再故意揖得过深，触发“过恭近谄”；
3. 打开反馈，查看规则出处和教学抽象；
4. 重新操作，完成合宜行为；
5. 演练后回到相关章句和复盘问题。

通过故意犯错展示系统能识别“过”与“不及”，避免演示变成单纯三维小游戏。

## 5.5 现场兜底

现场准备：

- 公网部署和手机热点双网络；
- 两台可运行演示的电脑；
- 冻结版本和本地数据；
- 模型不可用时的固定问题证据缓存；
- 图服务不可用时的文本路径；
- 不超过两分钟的核心功能备用视频；
- 每个关键步骤的静态截图。

兜底不能伪造实时能力。使用缓存或 Mock 时应向评委说明，并保留正常版本的测试和演示证据。

## 6.3 应用与推广验证

应用目标包括汉语国际教育课堂、大学生经典学习和文化机构教学活动。推广成果只报告真实发生的试用、合作和反馈。

优先获得的外部证据包括：

1. 教师对问题设计、答案边界和课堂流程的评价；
2. 学习者对出处查找和概念辨析的前后测；
3. 仪礼情境的任务完成与迁移表现；
4. 合作单位的试用记录；
5. 对失败案例和修改过程的公开说明。

## 6.4 创新点与特色

### 6.4.1 核心创新一：经—注—用分轨的论断级核验

普通生成式问答输出一段难以拆解的文本。本作品先将答案组织为经、注、用、译四类论断，再建立论断与证据片段的映射，对支持状态、发挥漏标和术语一致性进行核验。无依据内容被拦截、降级或明确警示。

成立条件：完成独立评测集、基线对比、分轨分类和论断支持实验。仅靠提示词分段不能证明该创新。

### 6.4.2 核心创新二：图文协同的可溯源证据检索

系统针对单句释义、注疏辨析和概念关系使用不同检索策略，联合原文、注疏、译文和带来源图谱路径形成分型证据束。图谱进入答案证据链，而不是只用于前端展示。

成立条件：图关系具有来源，融合方法可复现，并在多跳问题上通过消融实验证明增益。

### 6.4.3 应用创新：基于规则出处的仪礼情境演练与复盘

系统将迎宾、揖让、安席和照应形式化为有版本的状态机，让学习者能够体验过、不及和合宜，并查看规则来源、时代、范围及教学抽象。演练结果回到章句和复盘问题，形成从解释到实践的学习闭环。

成立条件：规则来源透明、状态机测试完整，并有用户学习效果证据。几何平均和三维场景本身不单独称为创新。

### 6.4.4 作品特色

- 论断与证据映射过程直接可见；
- 中文和英文跨语学习路径；
- 浏览器内完成仪礼情境，无需专用头显；
- 公网、容器和离线降级并存；
- 其他五艺和开放接口作为扩展展示。

| 时间 | 内容 | 评委应形成的判断 |

| 0:00—0:45 | 普通大模型的流畅错误或混层案例 | 问题真实且容易被忽视 |

> 我们不是让 AI 扮演孔子，而是让 AI 对每一句解释负责。

结尾句：

> 每一句有出处，每一种解释有边界，每一次学习都能进入实践。

### 一、立项背景

#### 1.1 题目释义：先收住「做什么」

「切问」指提问必须贴着文本与处境，不允许凭模型语感凭空发挥；「近思」指思考必须落到可做的事上，不允许只把仁、礼讲成抽象名词。二者合起来，才是本作品的边界：

- **切问**：面向儒家经典的问答，必须可溯源、可区分「原文依据 / 现代发挥 / 文化格义」；
- **近思**：把「礼」等修养做成可错、可练、可复盘的程序，而不是场馆科普或知识点测验。

后文一切模块，都只为这两件事服务。做不到切问或近思的功能，不进入本作品的主线。

#### 1.2 问题从哪里来

大模型把「问孔子」的门槛降到接近零。任何人用母语输入一句「What is ren?」，都能得到流畅、礼貌、像那么回事的回答。对文化传播而言，这既是机会，也是风险。

风险不在「模型不会说」，而在「说得越流畅，误读越难被发现」。我们把常见失败分成三类，它们对学习者的伤害并不相同：

1. **无出处（幻觉）**  
   编造篇名、错引原文、把后世注疏说成孔子原话。学习者以为「有经典依据」，实际无从核对。

2. **错时代（把现代观念读进论语）**  
   用当代人权、平等、心理疗愈等框架直接改写经文。发挥并非一概错误——国际传播恰恰需要当代转译——但必须标明「这是引申，不是原义」。若不加区分，经典被掏空，只剩现代话语的古典包装。

3. **错格义（用西方伦理范畴替换儒家概念）**  
   把仁译成并等同于 benevolence，把礼等同于 ritual manners，把恕等同于 Golden Rule。格义本是历史上以已有概念强解新说的方法；在跨语问答里，它会让人以为已经懂了，其实只是把儒家装进了另一套范畴。

与此同时，**礼是实践之知**。只讲解「宾主有序、揖让有节」，读得懂，做一次迎宾仍会乱序、过恭或怠慢。若系统只会聊天、不能练习，则「近思」落空，切问也停在口头。

因此，本作品要回答的不是「如何再做一个孔子聊天机器人」，而是：

> 在大模型已经能够流畅谈论儒家的前提下，如何让回答仍然可核对、可区分，并让人通过一次可计分的练习把「礼」做出来？

#### 1.3 国家需求与课题牵引

党的十八大以来，传承发展中华优秀传统文化被明确为「创造性转化、创新性发展」。对外文化工作则要求内容从「走出去」进一步做到「走进去」：不仅到达海外界面，还要进入对方的理解结构，避免符号误读与价值替换。

本团队工作依托中宣部相关课题，面向儒家经典的国际传播与教学辅助。课题需要的不是又一份宣传页或又一套语料统计，而是一个**可演示、可核对、可练习**的交互系统：海外学习者与汉教课堂问得清出处，分得清原义与发挥，挡得住以西释中，并能在浏览器里完成一次「执礼」而非只看解说。

课题是需求来源与应用背景，不是技术贡献本身。评述本作品，仍应看方法是否成立、系统是否可运行。

#### 1.4 技术背景：已有工具解决了什么、没解决什么

检索增强生成（RAG）将外部证据写入生成条件，是缓解大模型幻觉的主流路径（Lewis 等，NeurIPS 2020）。RAGAS 等评测把 faithfulness 定义为「生成论断能否被检索片段支持」（Es 等，EACL 2024）。对第一类错误（无出处），这条路线是对的，也是本作品切问的底盘。

知识增强则指出：仅靠向量相似不够处理「仁与礼、忠与恕」这类关系型、多跳问题。ERNIE、KEPLER 将知识图谱与语言表示结合（Zhang 等，ACL 2019；Wang 等，TACL 2021）；GraphRAG 用图结构服务全局与多跳问答（Edge 等，2024）。它们说明**结构化知识应当进入问答**，而不是只做前端展览。

跨文化评测（如 CulturalBench）表明，即便前沿模型在文化知识上仍有明显缺口（Chiu 等，ACL 2025）。但该类基准覆盖的是饮食、礼仪习俗等通识文化题，**不是经学意义上的格义问题**。把仁直接等同于 benevolence，在 CulturalBench 里未必算错，在儒家教学里却是核心误读。

因此，通用 RAG 的「忠实于检索片段」只覆盖切问的第一维。第二维（现代发挥必须显式标注）在通用评测里常被当成「超证据生成」而打负分，在传播场景里却是必要能力。第三维（文化格义）几乎不在现成指标里。近思所需的「过犹不及可计分」，更不属于 NLP 评测范围，而属于把价值写成规则的交互设计。

#### 1.5 立项意义（对谁有用）

| 对象 | 若没有本作品 | 本作品若做成 |
|------|----------------|--------------|
| 海外学习者、汉教课堂 | 流畅问答难以核对，概念在翻译中被替换 | 每句可点回原文；发挥与格义分开展示；五语可用 |
| 文化传播与课题任务 | 易用到达率、访问量代替理解质量 | 把「走进去」落在可校验、可练习，而不是页面浏览 |
| 学习者本人 | 懂一点名词，不会做一次礼 | 揖深浅、迎宾序、安席、照应时机可错可练 |

一句话：让儒家经典在大模型时代仍然**可核对、可区分、可练习**，避免国际传播变成流畅的误读。

### 二、国内外现状

同类工作很多。必须先承认：和孔子聊天、给《论语》做检索问答、画概念图谱、用 VR 体验射御，都已有人做。本作品不与之比较「模型是否更大、语料是否更多」，只比较**是否对准切问与近思**。

#### 2.1 国外：人设对话降低了门槛，很少做核对

英文世界已有多类「问孔子」产品。CGTN 的 Ask Confucius 以媒体传播为目的，提供与孔子对话、论语导读等入口，明确标注由 AI 生成、不代表机构立场。Historic Mentor、DeepAI 角色对话、Jenova 等「AI Confucian Scholar」则把孔子做成可陪伴的导师：强调《论语》与四书、日常伦理建议、自我省察。

这类产品的贡献是**降低接触门槛**，让海外用户愿意开口。其共同缺口也清楚：

- 少见论断级出处（哪一句、哪一章、能否点回原文）；
- 几乎不区分「原文本义」与「现代人生建议」；
- 翻译默认完成理解，很少处理格义（仁是否等于 benevolence）；
- 停留在「问」，没有「习」。

对切问近思而言，它们解决的是「愿不愿意问」，不是「问完是否问对、想完是否能做」。

#### 2.2 国内：领域模型与数字人文更强，目标不同

**（1）古籍大模型与孔子智能体**

南京农业大学「荀子」系列在开源通义等底座上做古籍领域续训与指令微调，覆盖句读、翻译、词法分析、知识问答，定位是古籍文本处理工具链，服务学习者与研究者。南京大学「子曰」智能体以孔子文献与专家知识库为基础，结合 RAG 与人类反馈，尝试复现「仁礼合一」的思考方式，并整理孔子形象的历史变迁，目标更接近「请教孔子回答当代之问」。

这两类工作在语料厚度、专家标准、模型训练上强于本科竞赛作品。答辩与说明书必须主动承认这一点。本作品不拼续训规模，也不把自己做成「孔子人格」。切问要的是**约束**（依据 / 发挥 / 格义可分），近思要的是**练习**（礼可计分），与「更会说古汉语」或「更像孔子」不是同一目标。

**（2）数字人文中的《论语》与图谱**

北京大学数字人文研究中心的《论语》文本复用可视化、文献溯源分析，面向历时互文与思想流传，服务的是学者阅读。另有基于《论语集注》手工抽取实体关系、用力导向图重构非线性阅读的知识图谱系统；以《左传》等为对象的图谱问答论文，则把问句解析为图查询。近年亦有以大模型抽取先秦文献三元组、存入 Neo4j 并做问答以缓解幻觉的探索。

这些工作证明：经典需要结构化，图谱对多跳关系有用。缺口在于——图谱多为**浏览或槽位式查询**，不一定进入生成式问答的每条论断；用户是文献研究者，不是跨语学习者；没有「格义」维，也没有可练习的礼。

#### 2.3 六艺数字化：有体验，少有「过犹不及」

图书馆与文旅场景中的 VR「君子六艺」，用头显完成射、御、编钟等体验，并配知识问答，适合场馆科普。亦有以六艺为卷宗主题的汉字填字等游戏。它们解决的是「愿意看一看、玩一玩」。

与近思相比，仍缺关键一步：把**敬、序、节**写成规则——揖过深为谄、过浅为慢，迎宾乱序要扣，过度殷勤失于节；并用几何平均体现「不可偏废」。若只是换皮小游戏或百科问答，六艺与切问脱节，题目就立不住。

计算机设计大赛中的文化类作品，近年多见古建数字展示、非遗图像修复、诗词微课、剪纸文创等，体现「数智赋能传统文化」。它们证明赛道认可文化主题，但很少把「可校验的经典问答」与「可计分的礼」做成同一件作品。本作品若写成门户或宣传站，会落入已有赛道的平均项；只有扣住切问近思，才与上述作品错开。

#### 2.4 综合评述：空白在组合，不在单点

| 类型 | 代表 | 已解决 | 未覆盖（切问近思所要） |
|------|------|--------|------------------------|
| 孔子人设聊天 | CGTN Ask Confucius、英文导师类产品 | 愿意开口 | 论断溯源、发挥/格义区分、可练的礼 |
| 古籍大模型 / 孔子智能体 | 荀子、子曰 | 领域能力、知识库与专家标准 | 三维校验作为显式方法；六艺程序化 |
| 数字人文图谱 | 北大论语复用与溯源、论语图谱、左传问答 | 互文、概念网、学者阅读 | 图谱进入生成式问答；跨语学习者；体感 |
| 六艺互动 | 场馆 VR、主题填字 | 科普体验 | 过犹不及可计分；与问答同一套思想 |
| 赛事文化作品 | 古建、修复、微课、文创 | 单点技术或传播形式 | 可校验问答 + 可练习的礼 |

单点上，本作品没有「世界首创和孔子聊天」或「世界首创知识图谱」。空白是：**同一系统里同时做到论断可溯源、现代发挥显式标注、格义可拦截，并把礼写成过犹不及的练习；图谱服务于切问，而不是只展览。**

#### 2.5 本作品在现状中的位置

相对国外人设产品，本作品少陪伴、多核对。  
相对国内领域模型，本作品不拼续训，拼约束与体感。  
相对数字人文系统，本作品面向跨语学习者，而不是只服务文献学者。  
相对 VR 六艺，本作品在浏览器中完成练习，并把计分规则接到经义（敬、序、节），再与切问的「不可偏废」对齐。

因此，国内外现状并不支持「再做一个更全的孔子平台」，只支持做一个**题目收得住的小系统**：问得切，思得近。

# 附录 B　界面设计规范

审美方向：**经折对读**。评委应在三秒内记住一件事——哪句话由哪条证据支持。

### 原则

1. 高大上靠纸本气质和留白，不靠水墨贴图或国潮贴纸。
2. 友好靠路径短：首页两扇门，底栏三个入口。
3. 颜色只服务分轨，不平均铺满。
4. 电脑、平板、手机、未来 App / 小程序共用同一套 token 与信息架构。

### 色彩

| 色 | 用途 |
|----|------|
| 宣纸暖灰 `#EDE6D6` | 页面底 |
| 墨 `#2A2622` | 经：原文与直接原义 |
| 深蓝 `#1E3A5F` | 注：注疏或学术解释 |
| 朱砂 `#8C3A22` | 用：现代发挥；主操作 |
| 金棕 `#8A6230` | 译：译法与术语差异 |
| 金线 `#C4A46A` | 选中对位，不是装饰金 |

深色模式保持同一语义，只提高对比，不改成冷黑科技风。

### 字体

- 标题与论断：Noto Serif SC / 宋体
- 英文引语：Source Serif 4 italic
- 界面短标签：系统黑体（PingFang / 鸿蒙 / 微信字体），保证小程序可复用

### 结构

- **首页**：竖排出典 + 一句立场 + 切问 / 近思两门 + 固定试问
- **切问**：论断卡（轨、状态、证据编号）↔ 证据卡（原文、出处、来源类型）
- **近思**：进入仪礼演练；反馈必须能点到规则出处
- **我**：账户与阅读记录；扩展功能不进主航

### 多端

| 端 | 对读方式 |
|----|----------|
| 电脑 | 左右开页 |
| 平板 | 右侧抽屉 |
| 手机 / App / 小程序 | 底部上滑 + 底栏「切问 / 近思 / 我」 |

预览：前端 `/design`，可切换电脑 / 平板 / 手机并点选论断看对位。

# 附录 C　答辩准备：更名后的内容调整与答辩建议

### 一、正式名称

**作品名称：**

> 《切问近思——可溯源、可核验、可演练的儒家经典交互学习系统》

这一名称保留了“切问近思”的文化出处，同时用“可溯源、可核验、可演练”概括作品的三项核心价值：

- **可溯源**：回答能够回到具体经典原文、注疏或译本；
- **可核验**：关键论断能够与证据逐条对应，并区分经典原义、注疏解释和现代发挥；
- **可演练**：经典义理能够进入可操作、可犯错、可反馈、可复盘的仪礼情境。

“可演练”比“可体感”更准确。除非作品后续真正加入摄像头姿态识别、动作捕捉或实体传感设备，否则“体感”容易使评委误认为系统包含体感硬件或人体动作识别。

---

### 二、内容上需要进行的调整

#### 2.1 重写项目开篇的问题定义

原稿主要按“切问、近思”两部分展开。建议保留这一文化解释，同时增加更清晰的“三重断裂”结构：

> 当前儒家经典智能学习存在三重断裂：  
> 一是答案与经典出处断裂，学习者无法判断“这句话从哪里来”；  
> 二是经典原义、历代注疏与现代阐释混在一起，学习者无法判断“这句话凭什么成立”；  
> 三是知识讲解与情境实践断裂，学习者知道“礼”的定义，却不能在具体情境中判断过与不及。  
>  
> 因此，本作品提出“可溯源、可核验、可演练”的儒家经典交互学习路径：让每条关键论断找到出处，让不同层次的解释能够被核对，让经典义理进入可以操作、犯错和复盘的情境练习。

这样处理后，作品名称、现实问题、功能设计和测试指标能够形成一致结构。

#### 2.2 给三个关键词下可验收的定义

三个关键词不能只作为宣传口号，应当分别对应系统机制、界面表现和评测指标。

| 核心价值 | 系统定义 | 评委可见结果 | 主要验收指标 |
|----------|----------|--------------|--------------|
| 可溯源 | 每条关键论断绑定具体原文、注疏或译本 | 点击论断跳转到书、篇、章句及证据片段 | 引用精确率、引用覆盖率、错引率 |
| 可核验 | 区分原义转述、注疏解释、现代发挥和术语说明，并判断证据是否支持论断 | 每条论断显示类型、证据和支持状态 | 论断支持 F1、无依据论断率、分轨分类 F1 |
| 可演练 | 将有出处的义理转化为可操作、可犯错、可复盘的情境 | 执礼、安席、迎宾等行为产生依据明确的反馈 | 规则覆盖率、状态机测试、学习前后测 |

这张表适合同时放在作品文档的需求分析部分和答辩 PPT 的前部。

#### 2.3 将“三维校验”改为“论断级核验”

“三维校验”容易被理解成三个缺乏依据的分数。建议改称：

> 经—注—用分轨的论断级核验

其中：

- **经**：经典原文及有直接出处的原义转述；
- **注**：历代注疏、现代学术解释及其明确来源；
- **用**：面向现代生活和跨文化传播的引申应用；
- **译**：必要时单独呈现跨语术语说明、不同译法和适用语境。

界面不应优先展示“依据分 87”“文化分 80”之类抽象数字，而应展示可读、可点击、可解释的论断核验结果。例如：

```text
论断 1：孔子将“仁”与“克己复礼”联系起来
类型：原义转述
证据：《论语·颜渊》12.1
支持状态：有直接依据

论断 2：这可以启发现代人反思个人欲望与公共规范
类型：现代发挥
状态：这是当代应用，不是孔子原话
```

#### 2.4 将知识图谱放回方法层

知识图谱仍然重要，但不应以“有一个图谱页面”作为主要卖点。它应当承担以下任务：

1. 处理“仁与礼是什么关系”等多跳问题；
2. 为概念、人物、篇章、命题之间的关系提供来源；
3. 进入问答检索和证据组织流程，而不仅服务可视化；
4. 在答案中只展示与当前问题相关的证据路径；
5. 将完整图谱浏览页面降为延伸功能。

评委需要看到的是“图谱解决了普通向量检索难以解决的问题”，而不是系统使用了 Neo4j。

#### 2.5 将“体感”统一改为“演练”

作品文档和界面建议统一使用以下术语：

- 仪礼情境演练；
- 行为操作；
- 状态反馈；
- 错误复盘；
- 情境学习。

如果未来加入真实动作捕捉，再将相关具体模块称为“体感交互”，不宜提前扩展到整个作品名称。

#### 2.6 将创新点收缩为“两项核心创新 + 一项应用创新”

建议重构为：

1. **经—注—用分轨的论断级核验机制**  
   回答不是一段不可拆解的生成文本，而是可以逐条核对的论断集合。

2. **图文协同的可溯源证据检索方法**  
   联合原文、注疏、译文和知识图谱，为单句释义、注疏辨析和概念关系问题提供不同证据。

3. **基于规则出处的仪礼情境演练与复盘机制**  
   将经典义理转化为有来源、有状态、有反馈的学习过程。

“切问—近思状态互馈”暂时作为系统特色。只有在用户实验能够证明其改善学习效果后，再将其升级为创新点。

#### 2.7 按三条价值主线重组功能

建议一级功能结构收束为：

```text
切问
├── 提问
├── 论断级核验
└── 出处阅读

近思
├── 仪礼情境
├── 行为反馈
└── 经典复盘

学习档案
├── 已读出处
├── 易错概念
└── 演练记录
```

知识图谱、账户、开放 API 和其他五艺应放入支撑功能或扩展内容，不再与三个核心价值并列。

### 三、如何给评委留下深刻印象

深刻印象主要来自：

> 一个尖锐的问题、一场明显的对比、一个看得见的原创机制、一组可信的数据。

#### 3.1 建立一句能够被记住的话

推荐作为开场或技术总结：

> 我们不是让 AI 扮演孔子，而是让 AI 对每一句解释负责。

推荐作为结尾：

> 每一句有出处，每一种解释有边界，每一次学习都能进入实践。

前一句负责技术记忆，后一句负责作品价值记忆。

#### 3.2 建立“一问、一验、一礼”的答辩结构

- **一问**：提出一个普通大模型容易回答得流畅却不严谨的问题；
- **一验**：逐条显示原文依据、解释层次和现代发挥；
- **一礼**：把其中的“礼”带入一个可以操作、犯错和复盘的情境。

评委未必会记住全部技术组件，但容易记住“一问、一验、一礼”。

#### 3.3 设计一个杀手级问题

推荐固定演示问题：

> Is *ren* simply equivalent to benevolence?

或：

> “仁”能不能直接翻译成 benevolence？孔子对“仁”有没有统一定义？

该问题能够同时展示：

- 跨语言提问；
- 多篇章检索；
- 不同语境中的“仁”；
- 核心概念不能被单一译词完全替代；
- 原义、注疏和现代解释的分层；
- “仁—礼”关系的图谱证据路径。

演示时可先展示通用大模型的流畅回答，再展示本系统如何拆分论断、绑定出处、标明边界，形成直接反差。

#### 3.4 开场先制造认知冲突

不建议先展示架构图。建议开场如下：

> 请看这段回答。它语言流畅、逻辑完整，也给出了《论语》的篇名。但其中有一句并不是孔子原话。对于不了解经典的学习者来说，越流畅，越难发现问题。

随后切换到本系统：

> 在《切问近思》中，模型不能用流畅掩盖证据不足。每一条关键论断都必须说明：它来自哪里，属于哪一层解释，证据是否真正支持它。

#### 3.5 让核验过程形成独特的视觉语言

建议形成稳定的界面语义：

- 墨色：经典原文；
- 深蓝：历代注疏或学术解释；
- 朱砂：现代发挥；
- 灰色警示：依据不足、存在争议或系统拒答；
- 论断编号与证据编号使用相同颜色或连线。

评委应当一眼看出“哪句话由哪条证据支持”。这一界面应成为作品最具辨识度的视觉资产。

#### 3.6 仪礼演示应故意犯错

不要只展示正确操作。推荐流程：

1. 面对尊者故意揖得过浅；
2. 系统指出“失之轻慢”；
3. 再故意揖得过深；
4. 系统指出“过恭近谄”；
5. 展示合理区间；
6. 点击反馈查看规则出处、时代和适用场景；
7. 重新操作，完成一次合宜行为。

演示中必须说明哪些规则直接来自文献，哪些属于教学抽象，不能将人为设置的角度阈值包装成历史事实。

#### 3.7 用一组可信数字支撑创新

最终答辩应形成类似以下证据：

> 在 600 道专家标注问题上，相较普通 RAG，系统将论断引用精确率由 X 提升到 Y，无依据论断率由 A 降低到 B；在学习者实验中，概念辨析正确率提高 C 个百分点。

其中的数字必须来自真实实验，不能提前编写。不要将“10 条测试全部命中”“标注语料单元总量”或种子用户数作为核心成果。

#### 3.8 使用真实学习者故事

未来真实试用中，可以记录类似案例：

> 一位英语学习者最初将“礼”理解为 manners。使用系统后，他能够区分礼仪行为、社会秩序和自我约束三个层次，并从答案跳转到相应章句和演练。

案例必须来自真实访谈或试用，并保留必要的原始记录和授权。

### 四、推荐的十分钟答辩结构

| 时间 | 内容 |
|------|------|
| 0:00—0:45 | 展示普通大模型的错误、混淆或无法核对案例 |
| 0:45—1:30 | 提出无出处、解释混层、知行断裂三个问题 |
| 1:30—2:00 | 提出“可溯源、可核验、可演练” |
| 2:00—4:30 | 杀手级问题现场演示，展示论断与证据映射 |
| 4:30—5:30 | 简要解释分轨生成和图文协同检索 |
| 5:30—7:00 | 仪礼场景故意犯错、查看依据、重新完成 |
| 7:00—8:20 | 展示基线对比、消融实验和用户研究 |
| 8:20—9:10 | 说明原创工作量、专家参与、部署与稳定性 |
| 9:10—10:00 | 总结“让 AI 对每一句解释负责” |

答辩中不逐个展示六艺，不展示完整后台。知识图谱可视化控制在 20 秒以内，仪礼交互控制在 90 秒以内。
